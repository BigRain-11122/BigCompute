# BigCompute 官方源核验（bigcompute-verify-official-source）

> 溯源＝集团技能动员令 P-2026-09-26-01（09-26 00:35）·T-13 法务核验批工作流沉淀（2026-09-26 立）。
> **唯一活账本＝`docs/research/R-20260924-verification-batch.md`**（本技能不复制其条目表与已判负渠道清单——引用不复制律·判负与否以活账本各 ⬜ 项内复抓日志为准）。

## §1 核验口径（四条铁律）

1. 查到＝官方原文逐字引用＋官方 URL＋抓取日期；查不到＝「仍未获得官方原文」如实记录。
2. **严禁用第三方转述/聚合站内容冒充官方原文**（记忆引证须显式标注且不可充当 ⬜ 回填依据）。
3. 平台后台类（需登录/商家后台导出）一律保持 ⬜，只给核验路径建议，禁编造保证金/费率/条款文字。
4. 一切结果对活账本**行级追加/更新，禁删行**（诚实律·编年史同源）。

## §2 工作流（五步）

1. **定位目标**：读活账本对应 ⬜ 项，取三指针（全景件位置／风险台账 R-xx／终审清单第 N 项）。
2. **抓取**：web_fetch 官方 URL。渠道优先序＝gov.cn 政策库/公报页 → 部委官网（samr/cac/nrta 等） → 国家标准全文公开系统 → 税务/地方官方站。
3. **导航壳判定**：页面无目标法规正文、仅栏目/导航链接＝gov.cn JS 渲染导航壳 → 按失败处理；有正文 → 逐字摘录关键字段（发文机关/文号/成文日期/条号/原文句），一项一字段不可意译。
4. **回填或记录**：
   - 成功＝活账本对应项更新 ✅（原文引用＋URL＋日期）＋指针联动回填（全景件/R-xx/终审清单——回填动作由当轮执行）；
   - 失败＝活账本该项追加一行复抓日志：`**<YYYY-MM-DD HH:mm> OSLoop 复抓**：<现象>`。
5. **三抓止损**：同一 URL 累计三次以上抓取仍壳/仍 412＝该渠道判负——维持 ⬜ 如实不造，结论固定为「终审前浏览器环境或人工开官方 URL 补核」；**禁继续盲抓消耗轮预算**（轮预算 ≤25 分钟·每次抓取须入轮账本 api 计量）。

## §3 输出纪律

- 复抓结果同步任务板 T-13 行（状态＋进展＋证据指针·如实）。
- 交叉验证优先：同文多官方源（政策库+公报+部委 PDF）互证后回填；单源新发现（如 2026 年 9 号公告类）只加注待核指针、不回填正典。
- commit 尾标 `[via BigCompute-OSLoop]`；轮账本 `api=<抓取次数>` 如实记。
