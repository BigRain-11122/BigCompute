- 28. 植入集完整性普查（T205／BC-P-194·11-04 立）：五个 drill 都靠「植入集含缺陷→检测器点名」自证，但没有任何东西能回答「植入集还在吗」——把某个缺陷用例删掉或改成合格值，drill 依旧打印 OK／零偏差（M119 的 `--bump-defects 1` 只证检测器有牙，证不了植入面没退化）。本条每轮跑 `drill_set_census.scan()`，按行判〔不信单行 banner〕：`DRILL-SET-SHRUNK`（案例数掉到钉死下限以下）／`DRILL-SET-DEGRADED`（计数对但缺陷位被改成合格值、或植入用例无期望）／`DRILL-SET-UNREADABLE`（读不到植入集）一律 FAIL 并**点名 drill 与 cases/defects 读数**；`N/A-NO-PLANTED-SET` 属显式声明的「本 drill 无植入集」，只打印不红门；但**全部行皆 N/A 时 FAIL**（一条也没测=没量）。未知 verdict 一律 FAIL 不臆测为健康。判据=selftest 九夹具（S1 全净 PASS 且报 drills/clean／S2 缩小 FAIL 点名／S3 零缺陷 FAIL 带 defects 计数／S4 不可读 FAIL 带错误／S5 单行 N/A 打印不红／S6 全 N/A FAIL／S7 无行 UNVERIFIED／S8 未知 verdict FAIL／S9 确定性）+ live `drills=… clean=…` 一行。

- 31. 渲染帧质检读数不许烂在回执里（T227／D-20261109-08 派生·11-09 立）：T226 量出 6 帧里 5 帧带 16%-65% 洋红占位像素，而旧闸只判 blank/duplicate 就放行；两读数（洋红占比／有效几何占比）加 `qc_verdict` 已写入渲染回执，但**没人复读的读数会烂**——有人删字段、或写入侧退回只判 blank/duplicate，没有任何一杖会响。本条直接读回执自己的 `frame_quality` 字段（**不读** `last_render_quality()` 的落盘重算路径——那会用 PNG 现算，恰好伪造出本探针要看守的那个读数）：①最近一条 `ok=true` 的 `render_spike` 回执无 `frame_quality` → FAIL；②带字段但 `magenta_pct`／`geom_pct`／`qc_verdict` 缺任一 → FAIL 点名缺键（**半个读数不是读数**）；③三键齐 → PASS 并回显 verdict；④从未渲染 → `qc=n/a(no-render-yet)` 不判红；⑤早于写入侧上线时刻（`FRAME_QUALITY_SINCE`）的旧回执 → `qc=pending(...)` **不判绿也不判红**（旧件不可能带字段，判红＝修不了的常红）。**只判字段存在与形状，不判数值高低**（D-20261109-08 只要求三键可见）。判据=selftest 六夹具（S1 从未渲染→n/a／S2 旧回执→pending 不许 PASS／S3 有回执缺字段→FAIL／S4 缺一键→FAIL 点名／S5 三键齐→PASS 回显／S6 失败回执不算「最近 ok 渲染」）＋live `qc=` 一行。
- 32. 派工判决必须自证「是否现测」（M177／M175 派生·11-09 立）：`dispatch_precheck`／`pool_igniter`／`gpu_idle_collector` 的每条判决都已写 `reading=(live|file)`，而 `lane_gate.verdict=STALE` 的意思恰是「心跳文件太旧，判不了」——这正是调用方本该现测的状态。没有 `reading`，这一行与「从没量过」在台账里长得一模一样，下一个改写法的人把字段丢掉也不会有任何一格变红。本条每轮读 `state/dispatch-gate.jsonl` 尾部 80 行：①`ts ≥ 2026-11-09 01:30`（M175 接线时点）的行凡缺 `reading` 字段一律 FAIL 并点名 `ts consumer(verdict)`——`reading` 是逐判决字段，`FRESH` 行同样必带（只判字段存在，不判判决对错）；②早于该时点的行只计入 `older=` **不判红**（历史行无法补写，判它就是修不了的常红，同第 31 条 legacy 分支）；③窗口内没有判决行 → `n/a(no-verdict-since …)` 不判红；④台账缺失/不可读 → FAIL（不许把「读不到」读成「没有 STALE」）；⑤PASS 行必带 `judged=/fresh=/stale=/file_stale=` 四读数，其中 `file_stale`=被判 STALE 却只读了文件的条数（随现测接线自然消解，读数可见即可，不单独判红）。判据=selftest 七夹具（S1 早于接线→只计数不判／S2 STALE 缺 reading→FAIL 点名／S3 FRESH 缺 reading→FAIL／S4 STALE 用 file 读数→PASS 且 file_stale 可见／S5 live 读数→PASS／S6 空台账→FAIL／S7 不可读→FAIL）＋live `reading=declared judged=… fresh=… stale=… file_stale=…` 一行。
- 33. `unknown` 的收敛读数必须仍然对得上盘（T230／T231·11-10 立）：`pool_igniter unknown-converge` 把回执里的 `unknown` 拆成 `computable / unprovable / known_bad` 写进 sidecar（`state/unknown-converge.json`），`pool_igniter status` 与 `batch_pool review` 都读它——但没有任何一格检查这份读数是否还描述**当前**回执。回执后来追加而没人重跑，两处读面就会安静地继续打印旧拆分，等于「读数加了没被守」。本条：①当前无 `unknown` 回执 → `n/a(no unknown receipts)` 不判红（**sidecar 缺席不算缺陷**）；②有 `unknown` 而 sidecar 缺席/不可解析 → FAIL（拆分从未算过，读面打印 n/a 会让集合看起来是空的）；③sidecar 缺 `ts／unknown／computable_count／computable_pass_count／computable_fail_count／unprovable_count／known_bad_count／receipts_sha256_after` 任一 → FAIL 点名该键；④sidecar 记录的 `receipts_sha256_after` 与当前 `state/pool-ignitions.jsonl` 的 sha256 不等 → FAIL 标 `STALE-SIDECAR`，要求重跑 `unknown-converge`，**禁读旧计数**；⑤`receipts_unchanged=false`（算的时候回执就在变）→ FAIL（不是一个快照）；⑥`computable+unprovable+known_bad ≠ unknown` → FAIL（计数不闭合）；⑦当前 `unknown` 数读不出（非整数）→ FAIL，不猜。**新鲜度按输入判、不按钟判**：回执逐字节未变时旧读数仍是真读数，纯时间阈值会在车道久关时造出修不了的常红（同第 31 条 legacy 分支、M173／M174 同族）——`age_h` 只作读数显示，不参与判定。判据=selftest 九夹具（S1 当前读数 PASS 且带 p/f 拆分／S2 无 unknown→n/a／S3 有 unknown 无 sidecar→FAIL／S4 回执变后→STALE-SIDECAR／S5 算时回执在变→FAIL／S6 计数不闭合→FAIL／S7 缺键→FAIL 点名／S8 unknown 不可读→FAIL／S9 sidecar 形状错→FAIL 且不崩）＋live `reading=current as_of=… age_h=… unknown=… computable=…(p/f) unprovable=… known_bad=… sha=…` 一行。
