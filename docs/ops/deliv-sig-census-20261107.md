## 二、三个真发现（都能改写下一步做法）

1. **115 件「产物」里 95 件就躺在回执目录**（`cph4/fleet/queue-receipts/`）。
   即这批的「产物」与「回执」是同一件东西——给回执补 node/id 等于给自己补，消费侧拿不到任何新增信息。
   真正独立于回执的产物只有 **20 件**（json 8 / text 12），签名率同样是 0（19 无签、1 半签）。
2. **媒体面在本机完全判不了**：7 日窗内 media 可检件 = **0**，全部落在 373 条他机回执里。
   所以「成片/关键帧带不带签名」这件事，本机既不能证实也不能证伪——之前任何把它算成「没签名」的说法都是越界。
3. **写侧格式漂移有实证**：`artifacts/bm-a/MANIFEST.jsonl` 带 UTF-8 BOM（读侧原判 UNREADABLE）；
   三件 `mv-transition*.json` 顶层是数组不是对象（NON-OBJECT，只能按「无 node/id 键」计，不能叫损坏）。

## 三、结论与边界

- **gate=STOP**：产物侧签名为 0，此前提到的「产物侧 overlay / 生成期挂钩子」都无处落地，不做。
- 下一步该动的是写侧（出件方），不是读侧：产物内加 `node`+`id` 两字段，成本一次一行；读侧随时能接。
- 边界：本机只读集团仓，不代改他机产物；22 件不在盘 + 373 件他机回执不归本司判真。
